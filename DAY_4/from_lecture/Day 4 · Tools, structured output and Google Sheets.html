01Why agents need tools

A model only knows what it learned and what is in the prompt. Tools let it fetch live facts and take real actions.

An LLM can't check today's stock, can't read your database, can't do reliable maths on big numbers and can't save anything. It only produces text. A tool is a normal Python function you allow it to use. The model decides when a tool is needed; your function does the actual work, exactly and safely.

Real world

When an assistant tells you the live status of your train or your parcel, it isn't remembering it; it called a tool that asked the railway or courier system. For Sweet Crumbs, prices can change and orders must be saved, so both need tools.

Analogy

A smart student in an exam hall can explain anything from memory, but can't tell you today's gold price or update the class register. Give them a phone and the register (tools) and they can.

02How function calling works

The model never runs your code. It replies with a request, "call get_price with these arguments", and your program runs it and sends the result back.

Along with the messages, you send a short description of each tool: its name, what it does, and its inputs. When the model needs one, its reply contains a tool call instead of text. Your code runs the function, adds the result to the messages as a tool message, and calls the model again. This is the agent loop from Day 3, made real.

03Writing good tools with @tool

In LangChain, @tool turns a normal function into a tool. The name, type hints and docstring become the description the model reads.

from langchain.tools import tool

MENU = {"plum cake": 500, "chocolate cake": 650, "cupcake": 80}

@tool
def get_price(item: str, qty: int = 1) -> str:
    """Get the total price in rupees for a quantity of one menu item.

    Args:
        item: Menu item, e.g. "plum cake", "chocolate cake" or "cupcake"
        qty: How many the customer wants
    """
    price = MENU.get(item.lower().strip())
    if price is None:
        return f"'{item}' is not on the menu. We have: {', '.join(MENU)}."
    return f"{qty} x {item} = Rs {price * qty}"

04The agent with tools: create_agent

Give create_agent a model, a list of tools and a system prompt. It runs the whole think → act → observe loop for you.

from langchain.agents import create_agent

agent = create_agent(model=llm, tools=[get_price, is_open], system_prompt=SYSTEM)

result = agent.invoke({"messages": [{"role": "user",
          "content": "Are you open on Sunday? And how much for 2 chocolate cakes?"}]})

for m in result["messages"]:      # the trace: every step the agent took
    m.pretty_print()
print(result["messages"][-1].content)   # the final answer

The result holds every message from the run: the question, each tool call, each tool result, and the final answer. Reading this trace is how you see what the agent actually did, and how you debug it.

05Rate limits and tool errors

Free API keys allow only a certain number of requests and tokens per minute. Agents make several calls per question, so they hit these limits faster.

When you go over the limit, the API answers with error 429 (Too Many Requests). LangChain's chat models retry a couple of times automatically (max_retries), but a busy agent can still run out. Three habits keep you safe:

  1. Own key per student. Limits are per account; twenty students on one key share one limit.
  2. Fewer, smaller calls. Short prompts, trimmed history, test with a few questions, not a hundred.
  3. Catch errors and reply politely (Day 2): try/except around the agent call; tools return messages instead of crashing.
llm = ChatGroq(model="openai/gpt-oss-20b", temperature=0.2, max_retries=3)   # retry 429s a few times

try:
    result = agent.invoke({"messages": [{"role": "user", "content": question}]})
    answer = result["messages"][-1].content
except Exception as e:                   # last line of defence for the customer
    print("Agent error:", e)             # you see the real problem…
    answer = "Sorry, I'm a little busy. Please try again in a minute."   # …the customer sees this

06Structured output with Pydantic

Describe the record you want as a Pydantic class. The model fills it in, and Pydantic checks every field before your code uses it.

On Day 2 you asked for JSON in the prompt and hoped for the best. Pydantic is a Python library that defines a record's fields and their types, and rejects data that doesn't fit. LangChain's with_structured_output makes the model reply in exactly that shape.

from typing import Literal
from pydantic import BaseModel, Field

class Order(BaseModel):
    """A cake order taken from a customer's chat message."""
    name: str = Field(description="Customer's first name")
    item: Literal["plum cake", "chocolate cake", "cupcake"] = Field(description="Menu item")
    qty: int = Field(description="How many", ge=1)          # ge=1: at least 1
    date: str = Field(description="Pickup date as the customer said it, e.g. '24 Dec'")
    eggless: bool = Field(description="True if the customer asked for eggless")

extractor = llm.with_structured_output(Order)
order = extractor.invoke("hi ravi here, need 2 plum cakes for 24th dec, eggless pls")
print(order)            # name='Ravi' item='plum cake' qty=2 date='24 Dec' eggless=True
print(order.qty * 500)  # 1000, a real int, ready for maths
Pydantic checks every fieldLive
Try qty = "two", then 0, then item = donut.
Real world

Online forms such as IRCTC or college admission portals won't let you submit an age of "abc" or a date in the wrong format. Pydantic is that form check for data coming out of a model, before it reaches your sheet, your bill or your database.

Analogy

A bank deposit slip checked at the counter. The cashier won't accept it if the amount box says "some money" or the account number is missing. Clean slips only.

07Saving to Google Sheets

A Google Sheet is the simplest database a small business already understands. In Colab, three lines connect to it.

from google.colab import auth
auth.authenticate_user()                 # a pop-up asks you to sign in with Google

import gspread
from google.auth import default
creds, _ = default()
gc = gspread.authorize(creds)            # gc = your Google Sheets client

sh = gc.create("Sweet Crumbs Orders")    # first time only; later: gc.open("Sweet Crumbs Orders")
ws = sh.sheet1                           # the first tab
ws.append_row(["name", "item", "qty", "date", "eggless", "total"])   # header row
ws.append_row(["Ravi", "plum cake", 2, "24 Dec", "yes", 1000])      # one order

append_row adds one row at the bottom. Each order becomes one row, and the owner sees it instantly on her phone in the Google Sheets app. (In Week 2, in VS Code, we'll use a service-account key file instead of this Colab sign-in.)

08Putting it together: the log_order tool

Wrap "check the order, work out the total, save the row" in one tool. The agent decides when an order is complete and calls it.

@tool
def log_order(name: str, item: str, qty: int, date: str, eggless: bool) -> str:
    """Save a confirmed cake order to the Orders sheet.
    Use only when the customer has given their name, item, quantity and pickup date."""
    try:
        order = Order(name=name, item=item, qty=qty, date=date, eggless=eggless)   # Pydantic check
    except Exception as e:
        return f"Could not save the order: {e}. Ask the customer to correct it."
    total = MENU[order.item] * order.qty
    ws.append_row([order.name, order.item, order.qty, order.date,
                   "yes" if order.eggless else "no", total])
    return f"Saved: {order.qty} x {order.item} for {order.name} on {order.date}, Rs {total}."

Notice what the docstring says: use only when all details are known. If the customer forgets the date, the agent should ask, not save half an order. The tool also double-checks with Pydantic, so even if the agent makes a mistake, a bad row never reaches the sheet.

One message, all the way to the sheetLive
Real world

This is the core of most business agents: understand a messy request, check it, act on it, confirm it. For now the agent saves straight away; on Day 7 we add an owner-approval step before anything is saved or sent.

Analogy

A careful billing clerk: listens to the customer, fills the order form, checks every box, writes it in the register and reads it back. The log_order tool is the form, the check and the register in one.

Cell 2 · Data, the Order model and three tools

from typing import Literal
from pydantic import BaseModel, Field
from langchain.tools import tool

MENU = {"plum cake": 500, "chocolate cake": 650, "cupcake": 80}
HOURS = {"monday": "9 am to 8 pm", "tuesday": "9 am to 8 pm", "wednesday": "9 am to 8 pm",
         "thursday": "9 am to 8 pm", "friday": "9 am to 8 pm", "saturday": "9 am to 8 pm",
         "sunday": "10 am to 6 pm"}

class Order(BaseModel):
    """A cake order taken from a customer's chat message."""
    name: str = Field(description="Customer's first name")
    item: Literal["plum cake", "chocolate cake", "cupcake"] = Field(description="Menu item")
    qty: int = Field(description="How many", ge=1)
    date: str = Field(description="Pickup date as the customer said it")
    eggless: bool = Field(description="True if the customer asked for eggless")

@tool
def get_price(item: str, qty: int = 1) -> str:
    """Get the total price in rupees for a quantity of one menu item.

    Args:
        item: Menu item, e.g. "plum cake", "chocolate cake" or "cupcake"
        qty: How many the customer wants
    """
    price = MENU.get(item.lower().strip())
    if price is None:
        return f"'{item}' is not on the menu. We have: {', '.join(MENU)}."
    return f"{qty} x {item} = Rs {price * qty}"

@tool
def is_open(day: str) -> str:
    """Check the bakery's opening hours for a day of the week, e.g. "sunday"."""
    hours = HOURS.get(day.lower().strip())
    return f"Open {hours} on {day}." if hours else f"'{day}' is not a day of the week."

@tool
def log_order(name: str, item: str, qty: int, date: str, eggless: bool) -> str:
    """Save a confirmed cake order to the Orders sheet.
    Use only when the customer has given their name, item, quantity and pickup date."""
    try:
        order = Order(name=name, item=item.lower().strip(), qty=qty, date=date, eggless=eggless)
    except Exception as e:
        return f"Could not save the order: {e}. Ask the customer to correct it."
    total = MENU[order.item] * order.qty
    ws.append_row([order.name, order.item, order.qty, order.date,
                   "yes" if order.eggless else "no", total])
    return f"Saved: {order.qty} x {order.item} for {order.name} on {order.date}, Rs {total}."

Cell 3 · The agent

from langchain.agents import create_agent

SYSTEM = """ROLE:   You are the friendly order assistant for Sweet Crumbs Home Bakery.
FACTS:  Orders need 24 hours' notice. All cakes have eggless versions.
RULES:  Always use get_price for prices and is_open for timings; never guess them.
        Before log_order, make sure you have name, item, quantity and pickup date; ask if missing.
        After saving, read the order back with the total.
FORMAT: Under 60 words, friendly, English or Telugu matching the customer."""

agent = create_agent(model=llm, tools=[get_price, is_open, log_order], system_prompt=SYSTEM)

history = []
def chat(text: str) -> str:
    global history
    try:
        result = agent.invoke({"messages": history + [{"role": "user", "content": text}]})
        history = result["messages"]                  # keep the whole run as memory
        return history[-1].content
    except Exception as e:
        print("Agent error:", e)
        return "Sorry, I'm a little busy. Please try again in a minute."

print(chat("Are you open on Sunday? How much are 2 chocolate cakes?"))
print(chat("I'm Ravi. Please book 2 eggless chocolate cakes for 24 Dec."))   # check your sheet!
